================================================================
1. game 34099 / 대구고 / 이현민(17)  R 2 -> sim 1 (-1)
================================================================

1-1. 결정적 증거: 득점 총합이 안 맞는다

  pitcher_box 실제값        정일(21) R=3, 이현민(17) R=2, 김민준(20) R=2  = 합 7
  경기 최종 스코어          대구고 4 : 대구상원고 7   -> 대구고 7실점 확정
  play-by-play 득점 행 합계  6점

  득점이 기록된 행은 아래 4개가 전부다.
    2회 seq8   서승환(27) 좌중홈  정일(21)    scored_run 7,8   2점
    3회 seq13  김성휘(10) 좌중2   이현민(17)  scored_run 1,3   2점
    7회        (폭투)             김민준(20)  scored_run 3     1점
    8회 seq35  서승환(27) 좌선2   김민준(20)  scored_run 7     1점

  합계 6점. 박스스코어와 최종 스코어는 둘 다 7점이다.
  -> 원본 기록지에 득점 1점이 누락돼 있다.

1-2. 왜 하필 이현민만 -1인가

  3회에 이닝 도중 교체가 있다 (정일 seq1~10 -> 이현민 seq11~20).
  seq13에서 2점이 나는데 scored_run "1,3" 중
    order 1 (피창현)  = 정일이 내보낸 주자  -> 부채 큐가 정일에게 귀속
    order 3 (남태웅)  = 이현민의 주자        -> 이현민에게 귀속
  이렇게 정일 3점(홈런 2 + 물려준 1), 이현민 1점이 되어 정일·김민준은 맞고
  이현민만 1점 부족해진다.

  즉 귀속 로직은 있는 데이터 안에서는 정상 동작했다. 없는 1점을 만들어낼 수
  없었을 뿐이다.

1-3. 해야 할 일

  코드 수정 대상이 아니다. 기록지에서 이현민 등판 구간(3~5회)의 누락된
  득점 1점을 찾아 채워야 한다. 채우고 나면 자동으로 맞을 것으로 예상된다.

2. game 34036 / 장안고 / 강준(12) +1, 안율(17) -1
================================================================

2-1. 현상

  pitcher_box 실제값   고정민(21) IP 3.0 BF 9  R 0
                       강준(12)   IP 3.0 BF 10 R 0
                       안율(17)   IP 1.0 BF 6  R 1
  경기 최종 스코어      장안고 37 : 화성동탄B 1   -> 장안고 1실점, 총합 일치

  득점 행은 단 하나다.
    7회 seq19  임형진(1) 좌월홈  pitcher 강준(12)   1점 (솔로 홈런)

  원본이 이 홈런을 강준이 맞은 것으로 적어놨고 시뮬레이션도 그대로 강준에게
  붙였다. 그런데 박스스코어는 안율 1실점이다.

2-2. 원인: pitcher 열이 한 타석 밀렸다 + 행이 파일 끝에 떨어져 있다

  IP를 보면 강준 3.0(4·5·6회), 안율 1.0(7회)이다. 즉 7회는 처음부터
  안율이 던졌고, 7회 첫 타자인 임형진의 홈런은 안율의 실점이 맞다.
  그런데 원본 seq19의 pitcher는 강준으로 적혀 있고, 안율은 seq20부터 시작한다.
  경계가 정확히 한 타석 밀려 있다.

  그런데도 BF는 왜 맞았나 — 파일 맨 끝에 plate_seq 없는 행 3개가 떨어져 있다.

    plate_seq  inning  batter      result        pitcher
    (없음)     4회     홍준호(56)  대수비        안율(17)
    (없음)     4회     이동호(14)  대수비        안율(17)
    (없음)     5회     최슬우(11)  대수비,삼진   안율(17)   <- 실제 타석(삼진)

  마지막 행은 5회의 실제 타석(삼진)인데 파일 끝에 있고 pitcher가 안율로
  적혀 있다. 5회는 강준이 던진 이닝이다.

  결국 두 개의 오류가 서로 상쇄된다.
    강준 : seq19(홈런)를 잘못 가져오고(+1), 5회 삼진 타석을 뺏김(-1)  -> BF 10 유지
    안율 : seq19를 뺏기고(-1), 5회 삼진 타석을 잘못 가져옴(+1)        -> BF 6 유지

  그래서 BF_diff는 0인데 실점만 엉뚱한 투수에게 붙었다.

2-3. 해야 할 일

  코드 수정 대상이 아니다. 기록지에서
    (a) seq19(7회 임형진 홈런)의 pitcher를 안율(17)로 정정
    (b) 파일 끝에 떨어진 5회 "대수비,삼진" 행의 pitcher를 강준(12)으로 정정하고
        위치/plate_seq를 5회 자리로 이동
  두 가지를 고치면 해결된다.

3. game 34032 / 경민IT고 / 이정수(38) +1, 장민기(1) -1
================================================================

3-1. 이 건만 진짜 알고리즘 문제다

  득점 총합은 정확히 맞는다 (박스스코어 합 15점 = play-by-play 합 15점).
  이정수 -> 장민기 교체 경계에서 1점의 귀속만 다르다.

    pitcher_box 실제값  이정수(38) R 5 (ER 3),  장민기(1) R 4 (ER 0)
    시뮬레이션          이정수     R 6,          장민기     R 3

3-2. 문제의 4회 전개

    seq20  김남휘(7)  1실    이정수   -> order 2 출루 (이정수 책임)
    seq21  김건(53)   중안   이정수   -> order 3 출루 (이정수 책임), 주자 1·3루
    --- 여기서 이정수 -> 장민기 교체. 이정수가 남긴 주자 2명 ---
    seq22  김윤우(10) 3땅R   장민기   scored_run 2   order 2 득점
                                       야수선택으로 order 3 아웃,
                                       타자 order 4가 그 자리에 출루
    seq23  김재훈(17) 좌안   장민기   scored_run 4   order 4 득점

  시뮬레이션의 판단:
    order 2 득점 -> 이정수 (남긴 주자, 정상)
    order 4 득점 -> 야수선택으로 물러난 order 3(이정수 책임)의 책임을 승계하므로
                    이정수. 결과 이정수 +2.

  실제 기록의 판단:
    order 2 득점 -> 이정수
    order 4 득점 -> 장민기

3-3. 왜 충돌인가

  현재 모델은 "야수선택으로 기존 주자가 아웃되고 타자가 그 자리에 들어가면
  타자가 그 주자의 책임투수를 승계한다"를 적용한다. 이 규칙은 2026 시즌
  38797 등에서 검증돼 지금 코드에 들어가 있는 동작이다.

  그런데 34032의 실제 기록은 정반대로, 야수선택으로 order 3이 물러난 순간
  이정수의 남은 책임이 소멸한 것으로 처리했다.

  참고로 ER을 보면 이정수 R5/ER3, 장민기 R4/ER0이다. 장민기의 4실점이 전부
  비자책이라는 뜻인데, 이는 order 4의 득점이 실책성 출루(1실, 3땅R)와 얽혀
  있기 때문으로 보인다. 자책/비자책 판정이 책임투수 판정과 다른 경로로
  이뤄졌을 가능성이 있어, 이 경기는 기록원의 판단이 개입했을 수 있다.

3-4. 해야 할 일

  둘 중 하나를 먼저 결정해야 한다.
    (a) 규정상 어느 쪽이 맞는지 확인 (9.16⒢ 야수선택 조항)
    (b) 이 경기 기록이 예외적 판단인지 확인

  (a)가 "장안식(=현재 기록)"으로 판명되면 FC 승계 규칙을 손봐야 하는데,
  그 규칙은 2026 시즌 여러 경기를 맞추기 위해 들어간 것이라 바꾸면
  2026이 깨질 가능성이 매우 높다. 반드시 아래 4의 절차를 지킬 것.
