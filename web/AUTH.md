# 로그인 (아이디·비밀번호 + 구글)

등급은 넷이다.

| 등급 | 되는 것 |
| --- | --- |
| **비로그인(guest)** | 지금까지와 똑같이 모든 기록 열람 — 로그인을 강제하는 페이지는 없다 |
| **로그인 사용자(user)** | 즐겨찾기 서버 저장(`/api/favorites`), 기록 오류 제보 |
| **파트너(partner)** | 공개하지 않은 선수·시즌, 랭킹 보정열, 구장 파크팩터 |
| **관리자(admin)** | 위 전부 + `/admin`(제보·계정·데이터 현황·상수·트래킹), `/predict`, 반출, 선수 상세의 Rapsodo 트래킹 구역 |

들어오는 문은 둘이다.

- **일반 이용자는 구글 로그인만** 받는다 — 비밀번호를 우리가 보관하지 않는다.
- **관리자와 파트너는 아이디·비밀번호**로 들어온다. 로그인 화면은 하나고, 칸에 넣은 자격이
  어느 쪽인지 정한다(`app/api/auth/login`). 화면에 '관리자용/파트너용'을 나눠 두지 않는 이유는,
  고르는 사람이 실수하고 그 화면만 보고도 관리자 계정이 있다는 걸 알게 되기 때문이다.

## 관리자는 둘로 나뉜다

등급은 넷이지만, 관리자 안에서 한 번 더 갈린다.

| | 주 관리자(owner) | 관리자 계정 |
| --- | --- | --- |
| 들어오는 곳 | 환경변수 `ADMIN_ID` — 딱 한 명 | 주 관리자가 `/admin` 에서 만들어 준 계정 |
| 저장 | `admin:credential` (바꾼 비밀번호만) | `admin:acct:<id>` |
| 되는 것 | `/admin` 전부 | **파트너 계정·관리자 계정 말고** 전부 |

다른 점은 **계정을 나눠 주는 일** 하나뿐이다. 파트너 계정 섹션과 관리자 계정 섹션은 주
관리자에게만 보이고, 그 두 API(`/api/admin/partners`, `/api/admin/admins`)는 목록을 주는
GET 까지 전부 서버에서 막는다(`denyUnlessOwner`) — 화면에서 안 그리는 건 보안이 아니다.
제보 처리, 구글 계정 목록·차단, 데이터 현황, 드래프트 입력, 공식과 상수, 공개하지 않은
시즌, `/predict`, `/api/export` 는 둘 다 똑같이 쓴다.

**계정을 나눠 주는 권한만 따로 떼어 두는 이유**: 파트너 계정 목록만 가려 봐야 소용이 없다.
본인이 파트너 계정을 하나 만들어 그 아이디로 들어가면 그만이다. 그래서 '계정을 만드는 일'
전체를 주 관리자 쪽에 둔다.

**누가 주 관리자인지는 쿠키를 믿지 않는다.** 세션에는 어느 쪽이든 `admin:<id>` 만 들어
있고, 볼 때마다 `ADMIN_ID` 와 견줘서 정한다(`lib/admin.ts` 의 `isOwnerSub`). 주 관리자
아이디는 여전히 환경변수 하나이므로, 저장소가 비어도 들어갈 문은 남는다.

관리자 계정도 **지우면 즉시 듣는다.** 세션 쿠키에 그 계정 비밀번호의 지문이 들어 있어서
(`pv`), 계정이 사라지거나 비밀번호를 다시 정해 주면 지문이 어긋나 그 자리에서 로그인이
풀린다. 만들기·재발급·삭제는 파트너와 같은 표를 쓴다(`lib/accounts.ts`).

## 파트너

파트너는 **밖의 사람**이다. 여럿이고 바뀌므로 주 관리자처럼 환경변수 한 쌍으로 끝낼 수
없어서, **계정을 표로 둔다**(`lib/partners.ts`, Upstash 의 `partner:<id>`). 표를 다루는 코드
자체는 관리자 계정과 같아서 `lib/accounts.ts` 한 곳에 있다.

1. 관리자가 `/admin` → **파트너 계정**에서 아이디·초기 비밀번호·메모를 적고 만든다
   (프로필 사진도 여기서 같이 넣을 수 있다 — 파트너는 구글처럼 사진을 받아올 데가 없어서,
   소속 로고 같은 걸 미리 붙여 두면 목록에서 알아보기 쉽다)
2. 관리자가 그 아이디·비밀번호를 당사자에게 전달한다
3. 당사자는 로그인한 뒤 **내 정보**에서 비밀번호를 바꾼다

저장소에는 scrypt 해시와 소금만 남는다(`lib/password.ts`) — **원문은 관리자도 다시 볼 수 없다.**
잊었으면 '비밀번호 다시 정하기'로 새로 정해 주고, 그러면 옛 비밀번호는 그 순간부터 못 쓴다.
아직 안 바꾼 계정은 목록에 '비밀번호 미변경'으로 표시되므로 누구에게 다시 말해야 하는지 보인다.

초기 비밀번호를 **아이디와 같게 두지 않는다.** 아이디는 어차피 같이 건네는 값이라, 하나만
새면 둘 다 새는 셈이 된다(`validatePassword` 가 아예 막는다). 아이디와 비밀번호는 따로 보내는
편이 좋다.

파트너에게 여는 것은 **기록뿐**이다. 운영 기능은 열지 않는다:

| 파트너도 본다 | 관리자만 본다 |
| --- | --- |
| 공개 색인에 없는 선수(졸업생·드래프트 지명자) | `/admin` 전체 — 제보 처리, 계정 목록·차단, |
| 공개하지 않은 시즌 (랭킹·팀 화면의 시즌 버튼) | 파트너·관리자 계정 만들기, 데이터 현황 |
| 랭킹의 보정열 (보정wRC+ · dwOBA · dFIP) | 공식과 시즌 상수 (`/admin/constants`) |
| 구장 파크팩터 (`/parks`) | 드래프트 예측 (`/predict`) |
| | 데이터 반출 (`/api/export` — 상수까지 통째로 나간다) |

오른쪽 칸 중 **파트너·관리자 계정 만들기**만 주 관리자 전용이고, 나머지는 관리자 계정도
같이 쓴다.

**파트너에게 따로 만든 화면은 없다.** `/admin` 은 열지 않는다 — 파트너가 얻는 건 운영 기능이
아니라 기록을 더 보는 것뿐이고, 그건 랭킹·팀 같은 평소 화면에서 그대로 일어난다. 열이 몇 개
더 붙고, 공개하지 않은 시즌을 고르는 버튼이 생긴다(`SeasonPicker`). 볼 것도 없는 화면을 하나
더 두면 '나는 뭘 할 수 있나'만 헷갈린다. 그래서 파트너의 계정 메뉴에는 **내 정보**와
**로그아웃**만 있다.

상단 바 탭은 **구장까지** 보인다. 파트너가 이미 보는 랭킹 보정열이 그 파크팩터로 계산된
값이라, 열을 주면서 근거를 감추면 그 숫자를 읽을 방법이 없다. 드래프트 예측과 공식·상수는
관리자만이다.

판정은 `lib/auth.ts` 의 `canViewPrivate` 한 곳으로 모았다. 화면에서 안 그리는 건 보안이
아니라서, 각 API 도 서버에서 같은 함수로 다시 막는다.

**계정을 지우면 즉시 듣는다.** 차단(`blocked`)은 쿠키를 그대로 두고 무언가를 *남기는* 순간에만
막지만, 파트너는 *읽는* 권한이라 그 수를 쓸 수 없다. 그래서 파트너 세션일 때만 볼 때마다 계정이
아직 있는지 다시 본다(`lib/auth.ts` 의 `canViewPrivate`). 저장소를 왕복하는 건 파트너로 로그인한
요청뿐이라, 비로그인·일반 사용자로 도는 대부분의 요청은 지금까지와 똑같다.

## 비밀번호 바꾸기

관리자와 파트너는 **내 정보**에서 본인이 바꾼다(`app/api/account/password`).

주 관리자 비밀번호는 원래 환경변수뿐이라 서버가 고칠 수 없었다. 그래서 **바꾼 비밀번호만
Upstash 에 두고(`admin:credential`), 없으면 환경변수를 쓴다**(`lib/admin.ts`). 관리자 계정은
처음부터 표에 있으므로 그 기록을 고친다.

- 한 번도 안 바꿨으면 지금까지처럼 `ADMIN_PASSWORD` 로 들어간다
- 바꾸면 그때부터 저장된 것이 이긴다
- **잊었을 때**: Upstash 에서 `admin:credential` 키를 지우면 환경변수 비밀번호로 되돌아간다.
  관리자는 한 명이라 '비밀번호 찾기'를 메일로 만들 수 없어서, 손으로 여는 문을 하나 남겨 뒀다
- 관리자 계정은 잊었을 때 주 관리자가 `/admin` 에서 다시 정해 준다 — 메일이 없으니 여기도
  손으로 여는 문이다
- 주 관리자 **아이디**는 못 바꾼다(`ADMIN_ID` 하나로 남긴다) — 저장소가 비었을 때 들어갈
  방법이 사라지면 안 된다

바꾸면 **다른 기기에 남아 있던 관리자 로그인이 그 즉시 끊긴다.** 세션 쿠키에 비밀번호 지문(`pv`)을
같이 넣어 두고 볼 때마다 견주기 때문이다. 바꾼 그 브라우저만 새 지문으로 다시 발급한다.

## 프로필 사진

본인이 고른 사진만 저장한다(`lib/avatars.ts`, Upstash 의 `avatar:<sub>`). 셋 다 쓸 수 있다.

**브라우저에서 256×256 정사각형 WebP 로 줄여서 올린다**(`lib/image.ts` — 내 정보와 파트너 계정
만들기가 같이 쓴다). 서버에서 이미지를 다시 그리려면 `sharp` 같은 패키지가 필요한데, 어차피 버릴
화소를 올리느라 시간을 쓰는 것보다 보낼 때 줄이는 편이 싸다. 다만 서버는 그 말을 믿지 않고
형식(webp/png/jpeg)과 크기 상한을 다시 확인한다.

파트너 계정은 만들 때 관리자가 사진을 넣어 줄 수 있다. 계정을 지우면 사진도 같이 지운다.

사진을 내려주는 통로(`app/api/account/avatar`)는 **세션 주인의 것만** 준다. 주소에 남의 식별자를
넣어 부를 수 있게 열면 그 순간부터 '누가 가입했나'를 훑는 통로가 된다.

구글이 준 프로필 사진은 여전히 저장하지 않는다(`lib/users.ts`) — 여기 들어오는 건 본인이 직접
고른 사진뿐이다.

## 구조

```
app/lib/session.ts   서명된 세션 쿠키(rp_session) 발급·검증
app/lib/auth.ts      권한 확인은 전부 여기 — getSession / requireAdmin / denyUnlessAdmin
                     계정을 나눠 주는 일은 isOwner / requireOwner / denyUnlessOwner
                     비공개 자료(관리자+파트너)는 canViewPrivate / requirePrivateView /
                     denyUnlessPrivateView
app/lib/kv.ts        Upstash Redis REST 얇은 래퍼 (rate limit 용으로 이미 있던 걸 같이 씀)
app/lib/users.ts     구글 로그인 계정 기록(user:<sub>) 읽기/쓰기
app/lib/accounts.ts  아이디·비밀번호 계정 표 — 만들기·대조·재발급·삭제. 파트너와
                     관리자 계정이 같이 쓴다
app/lib/partners.ts  파트너 계정 표(partner:<id>) — 표가 어디 있는지만 정한다
app/lib/admin.ts     관리자 자격 — 주 관리자(환경변수·admin:credential)와
                     관리자 계정 표(admin:acct:<id>)
app/lib/password.ts  scrypt 해시·무작위 비밀번호 — 관리자와 파트너가 같이 쓴다
app/lib/avatars.ts   프로필 사진(avatar:<sub>) — 저장·검사
app/lib/image.ts     사진을 정사각형으로 줄인다 (브라우저에서 도는 코드)
app/lib/oauth.ts     구글 설정과 콜백 주소 규칙
app/api/auth/…       google → google/callback → me / logout / login(아이디·비밀번호)
app/login            로그인 화면
app/admin            관리 화면(관리자만 — 계정 두 섹션은 주 관리자만)
app/components/AuthButton.tsx  상단 바 로그인 상태
```

설계에서 일부러 그렇게 한 것들:

- **세션은 쿠키 하나**로 끝낸다. 페이지 대부분이 정적 JSON을 읽는 구조라 요청마다
  Redis를 왕복할 이유가 없다. 쿠키에는 식별자·등급·표시 이름만 넣는다(서명돼 있을 뿐
  암호화된 게 아니다 — 이메일 같은 건 넣지 않는다).
- **로그인 상태는 클라이언트에서 `/api/auth/me` 로 물어본다.** 레이아웃에서 쿠키를 읽으면
  사이트 전체가 요청마다 다시 그려지는 동적 렌더링이 된다. 기록 페이지를 정적으로 남기는
  쪽이 훨씬 중요하다. 화면에 보이는 상태는 표시일 뿐이고, 실제 권한은 각 페이지·API가
  서버에서 다시 확인한다.
- **관리자 비밀번호를 바꾸면 발급된 관리자 세션이 자동 무효**가 된다(서명 키에 비밀번호를
  섞는다). 일반 사용자·파트너 세션은 영향받지 않는다. 전원을 로그아웃시키려면
  `SESSION_SECRET`을 바꾼다.
- `/admin`은 `TopNav`·홈 `SECTIONS` 어디에도 넣지 않는다 — `/predict`와 같은 이유로,
  관리자·파트너에게는 상단 바의 계정 메뉴로만 보인다.

## 환경변수

Vercel 프로젝트 설정에 넣는다. **값은 코드·커밋에 절대 넣지 않는다.**

| 이름 | 설명 |
| --- | --- |
| `SESSION_SECRET` | 세션 서명 키. `openssl rand -base64 32` 로 만든다. 바꾸면 전원 로그아웃 |
| `GOOGLE_CLIENT_ID` | 구글 OAuth 클라이언트 ID |
| `GOOGLE_CLIENT_SECRET` | 구글 OAuth 클라이언트 보안 비밀 |
| `AUTH_ORIGIN` | 이 배포의 주소(예: `https://rookiezpark.com`). 구글에 등록한 것과 글자까지 같아야 한다 |
| `ADMIN_ID` | 관리자 아이디. 화면에서 바꿀 수 없다 |
| `ADMIN_PASSWORD` | 관리자 **초기** 비밀번호. 화면에서 바꾸면 저장소 쪽이 이긴다 |
| `UPSTASH_REDIS_REST_URL` / `_TOKEN` | 이미 넣어둔 것. 계정 기록도 여기 저장된다 |

`AUTH_ORIGIN`이 없으면 요청 헤더로 주소를 짐작한다(로컬 개발용). Vercel 프리뷰는 배포마다
URL이 달라 구글이 거부하므로, **Preview 환경에는 브랜치 고정 주소를 `AUTH_ORIGIN`에 넣는다.**

없을 때 동작: `SESSION_SECRET`이나 구글 키가 없으면 **로그인만 안 되고 나머지 사이트는 그대로**
돈다(로그인 화면에 "설정이 준비되지 않았습니다"가 뜬다).

## 구글 클라우드 콘솔 설정

콘솔 메뉴 이름이 바뀌었다. 예전 안내에 나오는 "API 및 서비스 → 사용자 인증 정보"가 아니라
**Google 인증 플랫폼**(`console.cloud.google.com/auth`) 아래에 다 모여 있다. 메뉴를 찾기보다
주소로 바로 가는 게 빠르다.

1. [console.cloud.google.com](https://console.cloud.google.com) → 프로젝트 생성
2. [console.cloud.google.com/auth/overview](https://console.cloud.google.com/auth/overview) →
   **시작하기**: 앱 이름·사용자 지원 이메일 → 대상 `외부` → 연락처 이메일 → 만들기.
   (여기까지가 예전의 "OAuth 동의 화면"이다. 범위 선택 화면은 이제 안 나온다 —
   `openid`/`email`/`profile` 은 기본 범위라 따로 추가할 필요가 없다.)
3. [console.cloud.google.com/auth/clients](https://console.cloud.google.com/auth/clients) →
   **클라이언트 만들기** → 유형 **웹 애플리케이션**
4. 같은 화면의 **승인된 리디렉션 URI** — 쓸 주소를 전부 추가한다(글자까지 정확히).
   "승인된 자바스크립트 원본"은 비워둔다(서버 리디렉션 방식이라 필요 없다):
   ```
   https://rookiezpark.com/api/auth/google/callback
   https://<프리뷰 브랜치 주소>/api/auth/google/callback
   http://localhost:3000/api/auth/google/callback
   ```
5. 만들면 뜨는 클라이언트 ID·보안 비밀을 위 환경변수에 넣는다.
6. [console.cloud.google.com/auth/audience](https://console.cloud.google.com/auth/audience) →
   테스트 단계에서는 **테스트 사용자**에 로그인할 계정을 추가한다(추가 안 된 계정은 거부된다).
   아무나 로그인하게 하려면 **앱 게시**로 바꾼다.

## 아직 안 한 것

- 관리 화면의 데이터 갱신 버튼 (`/api/export` 는 아직 `EXPORT_KEY` 로만 호출)
- 파트너의 첫 로그인 때 비밀번호 변경 강제 (지금은 목록에 '비밀번호 미변경'으로 표시만 한다)

(제보 폼·제보 목록·계정 차단 버튼은 이미 들어가 있다 — 옛 메모라 지웠다.)
